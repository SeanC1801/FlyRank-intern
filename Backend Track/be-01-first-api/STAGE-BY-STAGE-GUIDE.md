## Part 1: Why are there so many files?

Here's every file/folder in your project and whether you actually need it:

```
be-01-first-api/
├── main.py              ✅ YOUR CODE — the only file you actually write
├── requirements.txt     ✅ NEEDED — tells Python what packages to install
├── README.md            ✅ NEEDED — explains your project to others (and for submission)
├── .gitignore           ✅ NEEDED — tells Git which files to NOT upload
├── .venv/               🔧 AUTO-GENERATED — Python's virtual environment (hundreds of files inside)
├── __pycache__/         🔧 AUTO-GENERATED — Python's compiled cache (speeds things up)
├── .idea/               🔧 AUTO-GENERATED — PyCharm/IDE settings (your editor created this)
└── .DS_Store            🔧 AUTO-GENERATED — macOS creates this in every folder
```

### The truth: You only write 3 files yourself

| File | You write it? | What it does |
|------|:---:|---|
| `main.py` | ✅ Yes | All your API code lives here |
| `requirements.txt` | ✅ Yes (2 lines) | Lists `fastapi` and `uvicorn` so others can install them |
| `README.md` | ✅ Yes | Explains your project |
| `.gitignore` | ✅ Yes (once) | Prevents junk files from being uploaded to GitHub |
| Everything else | ❌ No | Auto-generated by Python, your IDE, or macOS |

The `.venv/` folder alone has **thousands** of files inside — that's not your code, that's Python's installed packages. That's why `.gitignore` exists: to tell Git "don't upload `.venv/` or `__pycache__/`".

**Bottom line: Your entire project is essentially ONE file (`main.py`) plus a few small config files.**

### ✅ STAGE 0 — Hello, Server (you already did this!)

This is what you have right now:

```python
from fastapi import FastAPI

app = FastAPI(title="BE-01 First API")

@app.get("/")
def read_root():
    return {"message": "Hello from my first backend!"}

@app.get("/greet/{name}")
def greet(name: str):
    return {"greeting": f"Hello, {name}!", "endpoint": "greet"}
```

**Line-by-line:**
- `from fastapi import FastAPI` → Brings in the FastAPI library you installed
- `app = FastAPI(...)` → Creates your server. Everything hangs off this `app` object
- `@app.get("/")` → This is a **decorator**. It says "when someone visits `/`, run the function below"
- `def read_root():` → A normal Python function that returns a dictionary
- FastAPI automatically converts your dictionary `{}` into JSON

**How to run it:**
```bash
uvicorn main:app --reload
```
This means: "Hey uvicorn, look in `main.py`, find the object called `app`, and run it as a server. `--reload` means restart automatically when I save changes."

**Checkpoint:** Visit http://127.0.0.1:8000/ in your browser → you see JSON.

### 📝 STAGE 2 — Read: List and Single Task

**What changes:** Add an in-memory list of tasks + two GET endpoints.

**Add this code below your Stage 1 endpoints:**

```python
from fastapi import FastAPI, HTTPException    # ← update your import line!

app = FastAPI(title="Task API")


# ---------- In-memory "database" ----------
# This is just a Python list. It lives in your server's memory.
# When you restart the server, this resets. That's expected — no database yet.

tasks = [
    {"id": 1, "title": "Learn FastAPI", "done": False},
    {"id": 2, "title": "Build a CRUD API", "done": False},
    {"id": 3, "title": "Push to GitHub", "done": False},
]


# ---------- Stage 1 endpoints ----------

@app.get("/")
def root():
    """Describes what this API is."""
    return {
        "name": "Task API",
        "version": "1.0",
        "endpoints": ["/tasks"]
    }


@app.get("/health")
def health():
    """Health check — is the server alive?"""
    return {"status": "ok"}


# ---------- Stage 2 endpoints ----------

@app.get("/tasks")
def get_tasks():
    """Return all tasks."""
    return tasks


@app.get("/tasks/{task_id}")
def get_task(task_id: int):
    """Return a single task by its id."""
    # Loop through the list looking for a matching id
    for task in tasks:
        if task["id"] == task_id:
            return task
    # If we get here, no task matched — raise a 404
    raise HTTPException(status_code=404, detail=f"Task {task_id} not found")
```

**New concepts explained:**

| Concept | Explanation |
|---------|-------------|
| `tasks = [...]` | Your "database" — just a Python list of dictionaries. Super simple. |
| `HTTPException` | FastAPI's way to return error status codes. You give it a code and a message. |
| `task_id: int` | The `: int` tells FastAPI "this part of the URL is a number". FastAPI converts it automatically. |
| `raise HTTPException(status_code=404, ...)` | Returns a 404 response. `raise` means "stop here and send this error." |
| `{task_id}` in the path | This is a **path parameter** — the actual value comes from the URL (e.g., `/tasks/3` → `task_id = 3`) |

**Checkpoint:**
```bash
curl -i http://localhost:8000/tasks        # → 200, all 3 tasks
curl -i http://localhost:8000/tasks/1      # → 200, just task 1
curl -i http://localhost:8000/tasks/99     # → 404, error message
```

### 📝 STAGE 3 — Create: POST a New Task

**What changes:** Add a POST endpoint that accepts JSON and creates a task.

**Update the import line and add this below your Stage 2 code:**

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel              # ← add this import!


# ---------- Request body model ----------
# This tells FastAPI what shape the incoming JSON should have.

class TaskCreate(BaseModel):
    title: str                              # required, must be a string


# (... keep all your existing code: app, tasks list, Stage 1 & 2 endpoints ...)


# ---------- Stage 3 endpoint ----------

@app.post("/tasks", status_code=201)
def create_task(body: TaskCreate):
    """Create a new task. Send JSON with a 'title' field."""
    # Validate: title must not be empty
    if not body.title.strip():
        raise HTTPException(status_code=400, detail="Title must not be empty")

    # Build the new task
    new_id = max(task["id"] for task in tasks) + 1 if tasks else 1
    new_task = {"id": new_id, "title": body.title, "done": False}

    # Add it to our list
    tasks.append(new_task)

    # Return the created task with status 201
    return new_task
```

**New concepts explained:**

| Concept | Explanation |
|---------|-------------|
| `from pydantic import BaseModel` | Pydantic is a validation library that comes with FastAPI. It checks incoming data for you. |
| `class TaskCreate(BaseModel)` | A **model** — defines the shape of expected JSON. Like a form: "I need a `title` field, and it must be a string." |
| `body: TaskCreate` | Tells FastAPI: "Parse the request body as JSON and validate it against `TaskCreate`." |
| `status_code=201` | The default success code for this endpoint is 201 (Created), not the usual 200. |
| `body.title.strip()` | `.strip()` removes whitespace. `"   ".strip()` becomes `""`, which is falsy — so we catch blank titles. |
| `max(task["id"] for task in tasks) + 1` | Finds the highest existing id and adds 1. Simple auto-increment. |

**Why 201 and not 200?** HTTP has specific codes for specific situations:
- **200** = "Here's what you asked for" (reads)
- **201** = "I created something new for you" (creates)
- **400** = "Your request was bad" (validation failed)
- **404** = "That doesn't exist"

**Checkpoint:**
```bash
# Create a task (should return 201 + the new task)
curl -i -X POST http://localhost:8000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Buy milk"}'

# Verify it's in the list
curl http://localhost:8000/tasks

# Try with empty body (should return 422 — FastAPI's validation)
curl -i -X POST http://localhost:8000/tasks \
  -H "Content-Type: application/json" \
  -d '{}'

# Try with blank title (should return 400)
curl -i -X POST http://localhost:8000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"   "}'
```

### 📝 STAGE 4 — Update and Delete

**What changes:** Add PUT (update) and DELETE endpoints. After this, you have full CRUD!

**Add one more model and two endpoints:**

```python
# ---------- Request body model for updates ----------

class TaskUpdate(BaseModel):
    title: str | None = None       # optional — you might only update 'done'
    done: bool | None = None       # optional — you might only update 'title'


# (... keep all existing code ...)


# ---------- Stage 4 endpoints ----------

@app.put("/tasks/{task_id}")
def update_task(task_id: int, body: TaskUpdate):
    """Update a task's title and/or done status."""
    # Find the task
    for task in tasks:
        if task["id"] == task_id:
            # Check that at least one field was provided
            if body.title is None and body.done is None:
                raise HTTPException(status_code=400, detail="Provide 'title' and/or 'done'")
            # Validate title if provided
            if body.title is not None:
                if not body.title.strip():
                    raise HTTPException(status_code=400, detail="Title must not be empty")
                task["title"] = body.title
            # Update done if provided
            if body.done is not None:
                task["done"] = body.done
            return task
    raise HTTPException(status_code=404, detail=f"Task {task_id} not found")


@app.delete("/tasks/{task_id}", status_code=204)
def delete_task(task_id: int):
    """Delete a task by its id."""
    for i, task in enumerate(tasks):
        if task["id"] == task_id:
            tasks.pop(i)
            return                 # 204 = success, no content returned
    raise HTTPException(status_code=404, detail=f"Task {task_id} not found")
```

**New concepts explained:**

| Concept | Explanation |
|---------|-------------|
| `str \| None = None` | Means "this field is optional — it can be a string or absent". The `= None` sets the default. |
| `body.title is not None` | Checks if the user actually sent a `title` field. `None` means "not provided". |
| `enumerate(tasks)` | Gives you both the index (`i`) and the item (`task`) while looping — needed for `tasks.pop(i)`. |
| `tasks.pop(i)` | Removes the item at index `i` from the list. |
| `status_code=204` | 204 = "No Content" — success, but nothing to send back. Standard for deletes. |
| `return` (with nothing) | For a 204, you return nothing — the status code says it all. |

**🎉 You now have full CRUD!**

| Operation | Method | Endpoint | Status codes |
|-----------|--------|----------|-------------|
| **C**reate | POST | `/tasks` | 201, 400 |
| **R**ead | GET | `/tasks`, `/tasks/{id}` | 200, 404 |
| **U**pdate | PUT | `/tasks/{id}` | 200, 400, 404 |
| **D**elete | DELETE | `/tasks/{id}` | 204, 404 |

**Checkpoint — run the full cycle:**
```bash

  -H "Content-Type: application/json" \
  -d '{"title":"Buy milk"}'

# Update (mark it done)
curl -i -X PUT http://localhost:8000/tasks/4 \
  -H "Content-Type: application/json" \

# Read all (verify the changes)
```
